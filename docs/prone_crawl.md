# 双手双脚贴地爬行（prone crawl）动作序列

> 目标：先不训练，产出一套**可验证的开环爬行动作序列**（关节轨迹 npz）并播出来，
> 确认姿态、接触、推进方向都对，再拿去当 RL 参考步态。
>
> 姿态风格：**蜥蜴式四肢外展**，腹部贴地（躯干离地 9 cm），四肢向两侧摊开，
> 大腿/上臂近水平，膝/肘朝外上方折。含「站姿 → 俯卧」过渡段。

## 1. 一句话用法

```bash
# 根目录一键（默认拆成两个动作：站立->俯卧 + 向前爬行）
bash run_crawl.sh                  # 生成 + 验收 + 开窗回放（normal，0.12 m/s）
bash run_crawl.sh --no-replay      # 只生成 + 验收
bash run_crawl.sh --merge          # 遗留路径：不拆，出一整段（**已知不通过验收，见 §8**）
bash run_crawl.sh --preset fast    # 快档 0.5 m/s
```

> **默认且唯一推荐的路径是 `--split`**。四套（normal/fast × 动作 1/2）轨迹全部通过验收；
> `--merge` 只保留作对照，接缝处与末段会崩（a 达 3572 rad/s²），别拿去训练。

分步做：

```bash
cd sim/vendor/bxi_controller_ros2/src/bxi_example_py_elf3/launch
python prone_crawl.py --split                  # 生成两段轨迹
python prone_replay.py --traj <.../prone_gait_traj.npz> --mode kin --loop   # 看动作
cd - && python scripts/check_prone_crawl.py --traj <.../prone_gait_traj.npz>  # 验收
```

产物（`--split`）：

- `prone_standup_traj.npz`（动作 1：**站立 → 蹲下 → 双手撑地 → 双脚向后伸 →
  趴姿**，**5.0 s / 250 帧**，四阶段，不下跪）

- 场景 `elf3_prone.xml` + `prone_flat.xml`（自动生成）

- **合并动作序列**（见 §9）：`python scripts/build_prone_crawl_sequence.py [--preset fast]`
  产出 `prone_crawl_sequence_traj.npz`（normal 649 帧 / 12.98 s）= 动作 1 的 250 帧

- **网页 WASM 回放**（见 §9）：`python web/tools/bake_crawl.py` 把上面那份序列按关节名

  `logs/prone_crawl/a1_sheet_p1.png` / `a1_sheet_p2.png`（动作 1 十个阶段 × 两视角）、
  `a1_standup_final.gif` / `a2_gait_final.gif`
- 诊断：`python scripts/check_prone_entry.py [--preset fast|normal]` 打印过渡段分阶段
  实测表，并**直接核对 v9 顺序**（蹲下脚不动 / 手先撑地 / 脚单调后伸 / 后伸期手不
  离地）、断言「膝中心不高于髋」——改动作 1 先跑它；

  `python scripts/check_prone_exit.py` 跨两档扫描收腿段关节空间路径的时间分配
  （接触/中间段穿地、自碰撞、脚膝离地峰值）；

## 2. 姿态是怎么定义的

俯卧基座：`pos=(x, 0, 0.10)`、`quat=(0.7071, 0, 0.7071, 0)`（绕 +Y 前俯 90°）。
腹部由 `torso_collision` 的半径 0.09 撑住，实测最低点离地 1 cm。

在这个基座下，机器人局部轴与世界轴的关系是：

| 机器人局部 | 世界 | 含义 |
|---|---|---|
| +X | 向下 | 胸腔朝向地面 |
| +Z | 向前 | 头/前进方向 |
| +Y | 左侧 | — |

**这条映射决定了每个关节在爬行里的角色**（右表是本机 FK 实测灵敏度，基准姿态下给 +0.2 rad 看末端位移）：

| 关节 | 俯卧系里真正的作用 | 实测灵敏度 |
|---|---|---|
| `hip_y` / `shoulder_y` | 抬离地面（绕世界 Y） | +0.25 rad → 末端 ↑0.228 m |
| `hip_x` / `shoulder_x` | 水平面方位角（绕世界竖直轴） | ±0.2 rad → 末端水平 0.03~0.12 m |
| `hip_z` / `shoulder_z` | 沿肢体自身轴的扭转 | ±0.25 rad → 末端仅 0.005 m |
| `knee_y` / `elbow_y` | 折叠，改变接触半径 | +0.45 rad → 末端 ↑0.12 m、前移 0.075 m |
| `ankle_y` | 足尖压地角 | 接触高度微调 |

两个最容易写错的地方：

1. **前后扫掠由 `hip_x` / `shoulder_x` 承担，不是 `hip_z` / `shoulder_z`**。俯卧时肢体
   几乎水平，绕竖直轴的转动才是前后摆；`_z` 是纯扭转，拿它驱动会"原地扭不前进"。
2. **`hip_z` / `shoulder_z` 只为让肘/膝的铰链接近竖直**（膝往侧后方折、肘往侧前方折），
   否则膝一弯脚就翘到天上去（实测 knee=1.95、hip_z=0 时踝高 0.366 m）。

### 场景与光照

`write_scene()` 会从 `elf3.xml` 复制一份 `elf3_prone.xml`，并做五件事（都是幂等的）：

- 把地形 include 换成 `prone_flat.xml`（自包含：`assets.xml` + 棋盘格地板 + 平行光 + 出生点 site）。
- **地面用 40×40 的厚板（`box`），不用 `plane`**。`type="plane"` 的无限地面在
  `mujoco.Renderer` 离屏渲染里整块不出现（把它的 rgba 改成纯红，渲染逐像素不变），
  俯视时画面只剩天空球，看着像悬空。40 m 厚板顶面在 `z=0`，碰撞行为与无限平面一致。
- **地板贴棋盘格纹理**（`builtin="checker"`，`texrepeat=24` ≈ 每格 0.83 m）。纯色地板
  在俯视镜头里没有任何距离参照，姿态和位移都读不出来。
- **加一盏主光 `prone_key`，让它的光斑中心正好压在出生点 `(0, 0)` 上**。必须是定位光
  （`directional="false"`）—— 平行光只看 `dir`、完全忽略 `pos`。又因为 `dir` 是斜的
  （`-0.35 0.3 -1`，正下方直射会压出纯黑影子），灯不能放在 `(0,0)` 上方，得按
  `P.xy = SPAWN − (z/Dz)·D.xy` 反解到 `(0.910, −0.780, 2.6)`，否则光斑会被甩出 1.2 m。
  实测地面照度：中心 134 / 画面边缘 78，光斑肉眼可辨。
- **放宽 `<map zfar>`（2 → 100 m）和离屏帧缓冲（640×480 → 1280×720）**。前者是机身相机
  防外溢设的，会让 2 m 外的机器人和地面被整个裁掉；后者决定录屏分辨率上限。
- **删掉 `elf3.xml` 里那盏 `mode="trackcom"` 的灯**。它贴着头顶照、正下方投影，
  会在地面留一块纯黑圆斑；而把它的 `castshadow` 关掉又会让机器人整体变黑
  （这版 MuJoCo 的怪行为），索性删掉。`prone_key` 也**必须保持 `castshadow="true"`**，
  改成 false 会让整帧渲染成全黑。

`prone_replay.py` 里把 `site_rgba` 透明度置 0：`base.xml` 那个绿色出生点圆盘
`ut_spawn_origin` 在这个版本里会被渲染成**纯黑椭圆**（不是阴影），正好压在身体下方。

### 关节角加速度（电机能不能跟）

纯运动学回放的关节角加速度（`dt=0.02` 二阶差分）。下表是 **v7 拆段当时**的优化
历程（历史记录，v9 的当前值见 §6；量级与结论仍成立）：

| 指标 | 优化前 | 修完跳变（整段） | **拆成两动作后** |
|---|---|---|---|
| 全程最大 | **1507 rad/s²**（86 400 deg/s²） | **514**（接缝那一帧） | **172**（动作 1）/ **139**（动作 2） |
| 过渡段 / 动作 1 | 1507 | 399 | **171.6** |
| 循环段 / 动作 2 | 862 | 514 | **138.5** |
| 中位数 | 4 | 3~11 | 0.0 / 0.2 |
| p99 | — | — | 59.9 / 68.6 |

**1507 rad/s² 不是"动作快"，是 IK 分支跳变**：单帧 60~140°（帧 100→101 的
`shoulder_y` 从 −93° 跳到 +41°）。这类跳变的二阶差分能到 5e4 deg/s²，任何电机都跟不了。

根因有四个，逐个处理：

1. **冗余 roll 关节在零空间里游走**。`shoulder_y` / `hip_y` 是绕肢体纵轴的 roll，
   对末端位置几乎没有影响，但机械限位是 ±165°。IK 一边解任务一边被零空间先验推着
   转，帧 4→5 的 `hip_z` 直接跳 93°。
   → `smooth_roll()`：这两个关节**只做姿态装饰**，直接全轨迹高斯平滑（σ=4 帧），
   末端漂移 < 3 mm，跳变基本消除。
2. **过渡段关键帧时序与俯身进度不匹配**：原来 0.85 s 就要求手撑到 `z=0.045`，
   而那时 `pitch` 才 40°、肩还在 0.24 m 高 —— 目标距肩 0.37 m 但物理上够不到，
   IK 卡死在 `elbow=−55°` 限位（残差 36 cm），到 2.2 s 身体降下来才突然解开。
   → 把"撑地"关键帧推到 1.5 s（`pitch≈70°`）。
3. **IK 卡限位后出不来**：加"从设计姿态重启"（`solve_limb_robust`），
   并把多起点候选按"离上一帧最近"来选，而不是"链最低点最高"。
4. 残余跳变用 `rate_limit()` 摊平（120°/s，摆动相生效；支撑相放宽，
   否则会把支撑脚拖着走 —— 实测滑移从 21 mm 涨到 195 mm）。
   支撑相另加 `ground_clamp` 的**接触点 xy 锁定**，把水平漂移拉回本段起点。

### 拆成两个动作（`--split`，默认）

上面压到 514 之后，峰值就**卡在接缝那一帧出不去了**：第 131 帧（过渡段末 →
循环段首）的 `r_shoulder_y` 单帧差 55°，二阶差分 514 rad/s²。

这不是"动作太快"，而是**两段本来就是分别求解的**：过渡段走关键帧点插值、
循环段走相位目标，IK 在接缝处收敛到不同的冗余分支。试过的三种补丁
（关节空间缝合 / 接缝窗口限速 / 循环段开头沿用过渡段求解方式）都会把支撑脚
拖走，滑移从 28 mm 涨到 200+ mm。

**换个思路：既然接缝是人为拼出来的，就别拼。** 拆成两个独立动作后接缝不存在，
两段各自的峰值直接降到电机能跟的范围：

```bash
python prone_crawl.py --split      # 或在根目录 bash run_crawl.sh（默认就带 --split）
```

| | 动作 1 `prone_standup_traj.npz` | 动作 2 `prone_gait_traj.npz` |
|---|---|---|
| 内容 | 站立 → 蹲下 → 双手撑地 → 双脚向后伸 → 趴姿（**5.0 s，250 帧**，四阶段） | 向前爬行（normal 8 s / 400 帧、fast 3.4 s / 170 帧） |
| 角加速度峰值（fast） | **289.4 rad/s²**（u≈0.93 末段对齐 `l_shoulder_y`） | **164.9 rad/s²** |
| 接触点穿地（fast） | 6.4 mm | 7.7 mm |
| 中间段穿地（fast） | −0.5 mm（净空） | 1.5 mm |
| 关节余量（fast） | 11.0° | 13.6° |
| 自碰撞（fast） | 0 帧 | 0 帧 |
| 支撑相命中率 | 无支撑相（过渡动作） | 100% |
| 质心在支撑面内（normal） | — | **98.0%**（判据 95%） |
| 验收 | PASS（6 项判据 + 3 项 INFO） | PASS（9 项全过） |

normal / fast × 动作 1 / 动作 2 **四套轨迹均全项通过**（2026-11-09 回归，v9 四阶段版；
动作 1 的 0.44~0.74 是「双脚向后伸」，手在此期间钉住不动，见 §3.4）。
normal 档动作 1：穿地 6.5 mm / 中间段 −2.3 mm / 角加速度 152.4 rad/s² / 余量 11.0° / 自碰撞 0。

> 动作 1 只播一次、没有循环接缝，所以 `action_params(..., "standup")` 把限速放宽到
> 600°/s（normal 预设的 120°/s 是给循环步态用的）。不改这一条时 normal 档在
> u≈0.80 基座快速下降、腿被限速拖住，髋胶囊会穿地 20.2 mm。动作 2 仍用预设限速。

两段用了**不同的 IK 配置**（`action_params()`）：

- **动作 1 保持 4 自由度**。冻结 `shoulder_y` 后过渡段的手臂关键帧够不到
  （残差 157 mm），因为那一段手臂在空中大幅摆动，需要那个冗余度。
- **动作 2 冻结 `shoulder_y`**（`freeze_arm_roll=True`）。爬行段手臂只在接触点
  附近小范围移动，4 个关节解 3D 位置有 1 维冗余 → IK 在支撑相被推着游走，
  单帧跳 20°（实测）。冻结后解唯一，峰值 343 → 154。
  **腿不能冻**：`hip_y` 退出后髋部需要扭更多，髋部胶囊压到 −13.7 mm。
- 另外给动作 2 加了 `support_speed_scale=1.5`：支撑相也限速。
  之前不敢这么做（会把支撑脚拖走、滑移 195 mm），现在 `ground_clamp` 有
  **接触点 xy 锁定**兜底，实测滑移稳定在 23 mm 不变。

`--no-join` 可以把"动作 1 末段对齐到动作 2 首帧"关掉。默认开（**48 帧**五次
Hermite 收敛，可用 `--blend-frames` 改；v9 从 32 提到 48 的原因见 §3.4），
这样两个 npz 能直接连播；关掉的话接缝处差几十度（v7 实测 55°），
但**不影响任一动作内部**的角加速度。末段对齐后的 `ground_clamp` 不能带离地软约束：
实测会把 `r_hip_y` 一帧翻 72°（a=1008 rad/s²），这一条是踩过坑的。

### 相机（`--az / --el / --dist`）

**`--el` 负值才是俯视**，这是最容易踩的坑：`elevation` 是相机相对水平面的角度，
正值把相机放到**地面以下**仰视。实测 `el=+30` 时相机世界 `z=−1.21`，画面只剩渐变天空；
`el=−30` 才是"从斜上方 30° 往下看"。默认值就是 `az=105 / el=-30 / dist=2.2`，
即 3/4 侧后方的俯视 30°。

## 3. 动作序列

### 3.1 整体节奏

| 项 | 值 | 说明 |
|---|---|---|
| 采样 | 50 Hz（`dt=0.02`） | 与训练控制频率一致 |
| 周期 `T` | 2.0 s | 一个完整爬行循环 100 帧 |
| 占空比 `duty` | 0.75 | 支撑相占 3/4 周期，**始终 3 点支撑** |
| 目标速度 | 0.12 m/s | 每循环前进 0.24 m |
| 支撑期扫掠 | 0.18 m | 接触点相对身体后退的距离 = 步幅 |
| 摆动抬升 | 0.035 m | 峰峰值 41~43 mm（实测） |
| 循环数 | 4 | 8 s 爬行 |

### 3.2 四拍（对角序列）

四条肢体依次抬起，相位差 1/4 周期：

| 相位区间（t/T） | 抬起的肢体 | 支撑 |
|---|---|---|
| 0.00–0.25 | 左腿 | 其余 3 点 |
| 0.25–0.50 | 右臂 | 其余 3 点 |
| 0.50–0.75 | 右腿 | 其余 3 点 |
| 0.75–1.00 | 左臂 | 其余 3 点 |

> 为什么不是"左臂+右腿 / 右臂+左腿"的对角两拍：两拍时同时只有 **2 个支撑点**
> （恰好是对顶点），质心必然落在这条线段外 —— 实测只有 34% 的帧在支撑多边形内，
> 静态根本站不住。四拍 + 3 点支撑后升到 96%。

单肢内部：
- 支撑相（前 75% 周期）：接触点在世界系**固定不动**（由 IK 保证，零滑移），
  身体相对它向前推进 0.18 m。
- 摆动相（后 25% 周期）：从上一触地点前移到下一触地点（世界系前移 0.24 m），
  抬升剖面为「前 18% 快速离地、后 82% 缓慢落地」。

### 3.3 躯干

| 动作 | 幅值 | 相位 |
|---|---|---|
| 上下起伏 | ±6 mm（2 倍频） | `sin(2·2πt/T)` |
| 左右重心转移 | ±65 mm（1 倍频，fast 30 mm） | `-cos(2πt/T)`，**全周期不缓入** |
| 绕前进轴滚转 | ±2° | `sin(2πt/T)` |
| `waist_z` 反向配平 | ±2.9° | `-sin(2πt/T)` |

左右重心转移是**稳定性必需的**：矩形支撑（手在 x≈+0.42、脚在 x≈-0.75、y≈±0.36）
的对角线本来就穿过中心，质心离线只有 7 mm，不主动侧移就必然在某个 3 点支撑相里掉出去。
抬起顺序 l_leg(0-¼) → r_arm(¼-½) → r_leg(½-¾) → l_arm(¾-1)，要求 y 在前半周为负、
后半周为正，所以用 `-cos` 相位。

> **不要再给侧摆乘「从 0 缓入」的 ramp**（拆段模式）。那个 ramp 只在第一拍等于 0、
> 之后恒为 1，代价是：(a) 第一拍抬 l_leg 时重心还停在支撑三角形对角线 `l_arm-r_leg`
> 上（越界 13.5 mm，质心判据 94.5% → FAIL）；(b) 轨迹不再周期，第 400 帧 y 已偏 −A、
> 回到第 0 帧又回 0，`--loop` 播放时横跳 65 mm。去掉后接缝 y 差 0.1 mm、质心 98.0%。
> 只有合并模式（`entry_time>0`，过渡段末帧侧偏为 0）才保留缓入，否则接缝处同样横跳。

### 3.4 站姿 → 俯卧过渡段（5.0 s，四阶段；v9）

用户 2026-11-09 指定的顺序：**站立 → 蹲下 → 双手撑地 → 双脚向后伸 → 趴姿**。
这是 burpee 的分解：先蹲稳、手落地承重，再蹬腿成平板，最后胸腹落地。
v8 那套「蹲着先分腿、边前倾边伸臂、撑地后腿长时间静止、最后突然趴下」已废弃，
完整实现与标定留在 `logs/prone_crawl/backup_v8/`（本地存档，`logs/` 不入库）。

注意 `base_z` 是躯干中心高，不是髋高：俯身后
`hip ≈ (base_x − 0.36·sinθ, base_z − 0.36·cosθ)`、
`shoulder ≈ (base_x + 0.09·sinθ, base_z + 0.09·cosθ)`。

#### 几何命门：撑地时髋会后退 0.33 m，脚却还不能动

手撑地要求 `shoulder_z ≤ 0.545`（臂长 0.512 + 腕球 0.033），也就是躯干必须俯到
~68°、`base_z ≤ 0.49`。一俯身髋就往后退 `0.36·sin68° = 0.33 m`。若基座不前移，
髋掉到 x≈−0.33、跑到蹲姿脚（x≈+0.05）后方 0.38 m，IK 立刻落进「大腿水平前伸」
的坐姿分支。

v8 的解法是**把脚提前后撤到 −0.22**，代价正是「撑地前腿就动了、撑地后腿又不动」
——用户看到的「不协调」。v9 改成把**基座前移**：`x_frac` 在 u=0.44 拉到 **2.10**
（基座 x = 0.14×2.10 = 0.294），髋被拉回 x≈−0.06，脚仍在髋前 0.11 m，
手落在脚前 0.47 m。这才是标准 burpee 撑地姿势。脚后伸时基座退回 0.14、
脚推到 −0.68、髋 x=−0.24，腿自然向后伸直。

FK 探针（`logs/prone_crawl/probe_v9.py`）实测撑地瞬间：
肩 `(0.375, 0.178, 0.513)`、髋 `(−0.061, 0.136, 0.357)`。
撑地点取 `(0.40, ±0.24, 0.033)`，肩-手距 **0.484 m**，臂长余量 28 mm。
手 y 若沿用 v8 的 0.27，距离会顶到 0.508 m、IK 饱和。

#### 四条硬约束（改 `ENTRY_STAGES` / `entry_keys` 前必读）

1. **手撑地点必须贴着肩正下方，且手 y 要随阶段收放**。蹲姿/下探段手要抬到
   y=±0.44 绕开髋：收到 0.30 时 `elbow_y_collision` 会撞 `hip_z_collision`
   （实测 f91~120 共 30 帧自碰撞）。但撑地时 y 必须收回 0.24，否则超出臂长。
   `entry_keys` 的 y 序列是 `0.36 → 0.44 → 0.42 → 0.32 → 0.24`。
2. **撑地时脚要小幅后撤 0.15 m**。深蹲时大腿胶囊会水平前伸到 x≈0.25 / z≈0.29，
   正好挡在下探的上臂路径上（实测脚完全不动时 f99~120 仍有 21 帧肩/肘撞髋）。
   脚一后撤膝改为朝下折，通道让开；相对后面 0.61 m 的后伸量，这 0.15 m 只是
   「撑稳时的调整」，不改变动作顺序。配合手 x 从 0.37 提到 0.40，自碰撞归零。
3. **脚后伸段必须把 `hip_z` 锁在矢状面内**（`Params.entry_hip_z_limit = 25°`，
   只在 `u < EXIT_U` 生效）。腿 4 自由度解 3D 任务有 1 维冗余，脚一开始往后蹬，
   warm start 就跳到 `hip_z≈128° / hip_x≈71° / knee 141°` 的蛙式分支：
   踝 x 在 −177→−128 mm 之间来回甩、两条大腿在中线互穿。锁住之后 IK 残差
   从 441 mm 降到 0.3 mm、脚踝 x 单调后移。`u≥EXIT_U` 必须立刻放开，
   否则 `exit_leg_joints()` 收敛不到 gait 首帧的 `hip_z=+95°`。
4. **末段基座不能降太早**。0.88 的 `base_z` 若按 v8 压到 0.18，末段对齐
   （`blend_tail_to`，默认 48 帧）起点肩太低，右臂从「左臂镜像」插值到 gait
   首帧独立姿态时上臂会扫进地面（实测 f221~229 的 `r_shoulder_z_link` 到 −38.7 mm）。
   保持 0.26（与 v8 在 blend 起点的肩高相当），剩下的下降交给末段对齐完成。

#### 为什么 v8 看起来「不协调」

不是数值问题（v8 四套轨迹也全 PASS），是**动作编排**：

| | v8 | v9 |
|---|---|---|
| 脚第一次后撤 | u=0.30（还在下蹲） | u=0.38（撑地前一瞬，仅 6 cm） |
| 手撑地 | u=0.82（前倾了 0.34 u 才落地） | u=0.44 |
| 撑地之后腿 | 从 0.48 起静止 0.34 u | 立刻后伸 0.61 m（0.44~0.74） |
| 观感 | 蹲着慢慢扑倒、腿先摊开再不动、末段突然落下 | 蹲稳 → 撑住 → 蹬成平板 → 落趴 |

#### 收腿仍必须走关节空间（u≥EXIT_U=0.74）

这段沿用 v8 的结论：让 IK 自由解腿会落进 `hip_z≈−120°` 的蛙式分支，两膝挤到中线、
脚离地最高 43 cm，而验收脚本只查穿地下限、不查离地上限，会「数值全 PASS、画面全错」。
`exit_leg_joints()` 从 u=EXIT_U 的实际腿角出发，按 `hip_y` / `hip_x+hip_z` /
`knee_y` 三条各自的 smootherstep 收敛到 gait 首帧；`exit_end` 由 `build_split()`
先解动作 2 现取（两档、左右都不同：fast 左膝 96.9°、normal 52.3°）。
`u≥EXIT_U` 后跳过 `mirror_chain()` 的强制左右镜像，否则右腿被拉回左腿的值。
分档 timing 用「终点左膝角 75°」判定，见 `scripts/check_prone_exit.py`。

旧的两个补丁 `spread_hips()` / `lift_split_window()`（10° 外展偏置、14 mm 基座微抬）
仍然停用，别重新启用。

#### 末段对齐（`--blend-frames`，v9 默认 **48**）

`blend_tail_to()` 用五次 Hermite 把动作 1 末段收敛到动作 2 首帧。v9 在末段同时要
完成「基座 0.26→0.10、右臂从镜像→独立姿态、腿伸直→蟹式」三件事，32 帧时
`l_shoulder_z` 在 f232 顶到 **549.5 rad/s²**（判据 400）；摊到 48 帧后降到
**289.4 rad/s²**，中间段穿地同时从（32 帧 + `base_z=0.18` 时的）−38.7 mm 变成
−0.5 mm。`run_crawl.sh` / 生成器 / `build_split()` 三处默认都已改成 48。

试过但**排除**的修法：在 blend 之后补一次 `chain_clamp()` 想把上臂顶回地面以上，
结果 `r_shoulder_y` 在 f219~225 之间来回翻 150°、角加速度爆到 2712 rad/s² ——
那一区间的 IK 有多个等价折叠分支，「末端保持原位」的微调会跨分支。

`smooth_arm_joints()`（sigma=4，作用在 `u≥PLANT_U`）仍保留，削平手臂前移段的
jerk 尖峰；v9 的窗口是 `1−0.44=56%`（约 140 帧），比 v8 的 18% 宽裕得多。

#### 下蹲段腿部电机抖动与平滑（`leg_shake_sigma`，2026-11-09）

**现象**：v9 四套轨迹的数值验收全 PASS，但真机回放时「蹲下去的过程中腿部电机在抖」。
这类抖动用穿地 / 角加速度 / 自碰撞都查不出来 —— 它是**高频、小幅、来回反向**的
指令噪声，幅值只有几度，判据看的是峰值和下限。要看的是关节角一阶差分的**变号率**
和二阶差分 rms：

| 下蹲段 f0~60（fast，`hip_x` / `hip_z`） | 平滑前 | 平滑后 |
|---|---|---|
| 二阶差分 rms | 1.29 / 1.20° | **0.13 / 0.12°** |
| 二阶差分 \|峰值\| | 5.15 / 4.74° | **0.38 / 0.35°** |
| 一阶差分变号率 | 25.9 / 29.3% | **8.5 / 8.5%** |
| 最大穿地 | 6.5 mm | 6.4 mm（补接触后） |

**根因**：深蹲时脚目标几乎不动、腿近竖直，`hip_x`（髋外展）与 `hip_z`（髋旋转）
在任务 Jacobian 上高度退化，4 自由度解 3D 位置剩下的那 1 维冗余就由逐帧 IK 的
零空间先验决定。`q_nom` 每帧沿 `stand_chain → design_joints` 曲线变一点，这两个
关节就被往不同方向拽一点，解在流形上左右漂移；而 `hip_y` / `knee_y` 决定蹲深，
曲线本身平滑（rmsD2 0.12 / 0.25°），所以抖的只有这两对。左右严格镜像，同涨同落。
注意 `key_fracs` / `key_q` 那套 21 个关键姿态目前**解完没有参与主循环**（历史遗留
死代码），主循环是逐帧 `solve_limb_robust`，所以别指望靠加密关键帧解决。

**修法**：`smooth_leg_joints()` 在 `build_split()` 的**最末尾**（所有 `blend_tail_to` /
`ground_clamp` / `plant_clamp` 之后），只对 `f0~PLANT_U` 窗口内 `l/r_hip_x`、
`l/r_hip_z` 四条曲线做端点羽化的高斯低通，`leg_shake_sigma=2.0`：

* 首尾各 `r=int(2.5σ)` 帧用 smootherstep 权重从原值渐变到平滑值，`w[0]=w[L-1]=0`，
  站姿首帧与撑地帧严格保持，窗口外一个字节不动，末段 48 帧对齐区完全不受影响。
* **必须羽化**：硬端点保持会在窗口边界留下 C1 断点，实测 `|d2|max` 从 6.26° 反涨到
  14.95°。
* 只动冗余自由度，不碰 `hip_y` / `knee_y` —— 平滑主屈伸会把下蹲曲线本身抹钝。
  `scripts/check_prone_shake.py` 里专门有一条 `rmsD1 ≥ 0.5°` 的反向判据防这个。
* 低通让脚掌最低点下沉约 2 mm（−6.5→−8.4 mm），随后补一次 `ground_clamp`
  （`flags=None`，只抬不降，`ik_null=0` 从平滑后构型出发）把它买回 6.4 mm。
  这一步放在平滑**之后**、且不再有其它重解，否则 IK 会把关节角推回漂移点。

**试过但排除的两条路**：

1. 在生成阶段给腿单独用一份 `ik_null=0` 的 IK 参数（关掉零空间先验）：抖动确实减半，
   但冗余自由度一路漂到限位，中间段穿地 **17.4 mm**、自碰撞 **111 帧**。抖动必须在
   关节空间后处理，不能动已标定好的 IK 解。
2. 加大 `sigma` 到 3~4：全窗口 rmsD2 只再降 0.02°，踝位置漂移却从 16 mm 涨到
   28~32 mm，接触补正帧数变多，收益不抵风险。

改动作 1 或调 `leg_shake_sigma` 后跑两档：
`python scripts/check_prone_shake.py [--preset fast|normal]`（打印上面那张表并给
退出码），再跑 `check_prone_entry.py` 核对四阶段顺序没被破坏。

#### 其它易错点

- **`gait_hand` 的 y 是「左右绝对值平均」的正数，`entry_keys` 末键必须按侧加符号**
  （`gh_side = [gh.x, sg·|gh.y|, gh.z]`）。直接 `gh.copy()` 会把右臂目标放到 +y
  同侧，跨中线 0.54 m 远超臂长，末段 `r_arm` IK 残差 441 mm，只靠 blend 硬盖过去。
- **`plant_clamp` 的起点 `PLANT_U=0.44` 不能提前**：早了会把还在半空的手硬按到地面。
- **验收不查离地上限**：动作 1 末段（u≈0.80~0.95）脚会有一个平滑的离地鼓包，
  峰值约 80 mm，末帧回到 34 mm。这是 gait 首帧本身就是「左腿抬起」摆动相位的
  必然结果；要四肢全贴地得改动作 2 的起始相位，不能只在动作 1 里改。
  改末段时务必同时看 GIF / `a1_sheet_p*.png`，不能只盯数字。
- **过渡段所有「重解 IK」的收尾都要带离地软约束**（`guard_floor`）：
  `smooth_branches` / `ground_clamp` 不带时会把肘和上臂推进地面。

## 4. 关节解算方式

不是手调关键帧，而是**触地点驱动 + 逐帧 IK**：

1. 定义四个触地点（身体系）：手 `(0.42, ±0.30)`、脚 `(-0.75, ±0.30)`，高度由
   参考 IK + 接触闭环解出来（不能写死：足尖相对踝原点的下垂量随姿态在 58~92 mm 之间变）。
2. 支撑相把触地点钉在世界系固定位置，摆动相沿抬升弧线前移。
3. 每帧对每条肢做 4 自由度阻尼最小二乘 IK，目标 = 踝/腕原点；零空间用一个「设计姿态」
   做先验（决定肘/膝往哪边折）。
4. 支撑相再做一次**接触高度闭环**：量该肢所有 collision geom 的最低点，把目标 z 往下
   修一点，直到最低点 = `-press`（默认 -5 mm 预压）；收敛后的高度存进 `zbase`，
   摆动相从 `zbase + 抬升` 起跳（否则落地瞬间会下扎 3 cm）。
5. 最后一遍**穿地兜底**：任何一帧仍低于接触面就把它抬回去（只抬不降，不改水平位置）。

两条踩过的坑，写在这里免得重犯：

- **IK 的零空间先验不能用「JᵀJ + wI 同时吃先验」**：站立姿态腿几乎伸直，末端 z 对关节
  的灵敏度只有 0.1，先验项会把任务残差钉死在 40%（实测 3.7 mm 都追不回来）。
  必须先解任务、再把零空间分量投影给先验。
- **零空间步长 >0.1 会在跨段时翻肘**：实测 `ik_null=0.15` 时 r_shoulder_y 单帧跳 0.62 rad
  （31 rad/s），降到 0.02 后最大关节速度 3.9 rad/s。

另外 **设计姿态不能落在关节限位或奇异位形上**：`elbow_y=+90°` 是手臂伸直奇异
（腕离肩最远 0.512 m），设计值取 0.35 远离它；`knee_y≈0` 是腿伸直奇异，设计值取 1.10。

| `body_z` | 0.10 | 俯卧躯干高（腹部留 1 cm） |
| `body_sway` | 0.065 | 左右重心转移幅值（决定静态稳定性） |
| `body_bob` | 0.006 | 上下起伏 |
| `clearance` | 0.035 | 摆动抬升 |
| `press` | 0.005 | 接触预压（给物理留接触力） |
| `arm_touch` / `leg_touch` | (0.42, 0.36) / (-0.75, 0.36) | 动作 2 的触地点（身体系）；fast 档 (0.50,0.36)/(-0.64,0.28)。y=0.36 别随手收窄（见 §8 质心那条）。动作 1 的过渡段另走 `entry_keys` 世界系关键帧，不受这两项控制 |
| `swing_up` | 0.18 | 抬升剖面（1.0 = 整段正弦，高速档用） |
| `entry_time` | 5.0 | 过渡段时长 = 250 帧（`--no-entry` 关掉）。四阶段里 0.44~0.74 的脚后伸要走 0.61 m，压短这个时长会被 `rate_limit` 削顶（standup 档限速 600°/s） |
| `entry_hip_z_limit` | 25.0 | v9：脚后伸段（`u<EXIT_U`）把 `hip_z` 锁在 ±这个角度（度）内，否则 IK 掉进蛙式分支；`u≥EXIT_U` 自动放开，让收腿能到 gait 首帧的 +95° |

| `leg_shake_sigma` | 2.0 | 下蹲窗口 `f0~PLANT_U` 内 `l/r_hip_x`、`l/r_hip_z` 四条曲线的端点羽化高斯低通（帧），削掉真机上「蹲着腿在抖」；0=关闭。改完跑 `check_prone_shake.py`，详见 §3.4 末 |

改速度时注意：`speed` 变大→步幅 `v·duty·T` 变大→手的最远端可能超出可达半径。
### 速度上限（实测）

扫掠行程 = `v·duty·T`，速度越高前后极限就离身体越远。0.12 m/s 时实测：

| 量 | 实测范围 | 可用范围 |
|---|---|---|
| 腕-肩半径 | 0.203 ~ 0.388 m | 0.153 m（`elbow_y=-55°` 折到最紧）~ 0.512 m（`elbow_y=+90°` 伸直奇异，不能顶） |
| 踝-髋半径 | 0.406 ~ **0.591** m | ≤ 0.64 m（大腿+小腿） |

往上扫速度：

| speed | IK 残差 | 肘最小 | 踝-髋最大 | 结论 |
|---|---|---|---|---|
| 0.12（默认） | 0.30 mm | -43.2° | 0.591 | ✅ 腿还有 8% 余量 |
| 0.14 | 0.30 mm | -48.3° | 0.619 | ✅ |
| 0.15 | 0.30 mm | -50.7° | 0.632 | ✅ 勉强（腿只剩 1 cm） |
| 0.155 | **82 m** | -51.8° | **0.639** | ❌ 腿伸到头，IK 崩 |

**约束是腿的伸展（0.64 m），不是手**。所以 0.15 m/s 是硬上限，0.12 m/s 是留了 8% 余量的默认值。
真要更快，得同时把 `leg_touch` 往回收（脚更靠身体）或减小 `duty`，光抬 `speed` 会直接让轨迹失效。

### 提速到 0.5 m/s（`--preset fast`）

`v = 步幅 /(duty·T)`，三个旋钮只有两个能大动：

| 杠杆 | 能不能用 | 原因 |
|---|---|---|
| 加步幅 | ❌ 有限 | 腿伸到 0.64 m 就到头，0.15 m/s 时已经用掉 92% |
| 缩周期 `T` | ✅ 主力 | 步幅不变，靠加快节奏 |
| 降 `duty` | ✅ 配合 | 摆动时间变长 → 脚速 `v/(1-duty)` 变低 → 关节不用那么快 |

最终这组（实测能解出、IK 残差 0.30 mm）：

```python
speed=0.5, cycle_time=0.8, duty=0.6,          # 步幅 0.24 m，40 帧/循环
leg_touch=(-0.64, 0.28), arm_touch=(0.50, 0.30),   # 脚收进来腾伸展余量，手往前挪补手臂余量
body_sway=0.030, clearance=0.040, swing_up=1.0     # 侧摆减半、抬升改整段正弦
```

**为什么 `duty` 必须降到 0.6**（这是最关键的一步，实测对比）：

| 方案 | 步幅 | 摆动脚速 | 关节速度峰 | 支撑 | 质心覆盖 |
|---|---|---|---|---|---|
| duty=0.75（3 点支撑） | 0.24 m | **2.00 m/s** | **26.6 rad/s** ❌ 机器执行不了 | 全 3 点 | 52% |
| duty=0.60（本档） | 0.24 m | 1.25 m/s | **9.4 rad/s** ✅ | 3 点 + 37% 的 2 点 | 26% |

两档验收对比（`--preset normal` vs `--preset fast`）：

| 项 | normal（0.12） | fast（0.5） |
|---|---|---|
| 周期 / 帧数 | 2.0 s / 100 帧 | 0.8 s / 40 帧 |
| 步幅 | 0.18 m | 0.24 m |
| 接触命中率 | 100% | 100% |
| 最大穿地 | 5.6 mm | 6.1 mm |
| 支撑相滑移 | 26 mm | 22 mm |
| 关节离限位 | 9.9° | 9.9° |
| 关节速度峰 | 3.9 rad/s | **9.4 rad/s（2.4 倍）** |
| 质心在支撑面内 | 96% | 26%（判据降级为 INFO） |

**代价必须说清楚**：

1. **不再是准静态步态**。37% 的帧只有 2 点支撑，两点支撑的"支撑多边形"退化成一条线段，
   质心不可能严格落在内部 —— 所以 `check_prone_crawl.py` 对 `v>0.25` 的轨迹把这条判据
   降级成 `[INFO]`（只报告不判定），其余 6 项照旧严格。它不是放宽标准，是这条判据
   本身只对慢速步态成立。
2. **关节速度 9.4 rad/s**（约 540°/s），是基线的 2.4 倍。执行器在这个速度下能给多少力矩
   是另一回事，物理回放会比基线更差。
3. **物理上很吃紧**：整机 43.2 kg / 424 N，腹部摩擦系数 1.0，足底只有 0.6。腹部哪怕只承担
   20% 体重，拖拽力就是 85 N、功率 42 W，得由 3 条（常常只有 2 条）支撑肢的摩擦力出。
   0.5 m/s 更适合当成"训练时探索的上界"，而不是保证能跑到的指标。

用法：

```bash
python prone_crawl.py --preset fast        # 生成 prone_crawl_fast_traj.npz
python scripts/check_prone_crawl.py --traj .../prone_crawl_fast_traj.npz
python prone_replay.py --traj .../prone_crawl_fast_traj.npz --mode kin --loop
# 或者一键：bash run_crawl.sh --preset fast
```

## 6. 验收指标（`scripts/check_prone_crawl.py`，当前实测）

下表是 **`--preset fast`（0.5 m/s）** 的当前实测（2026-11-09，v9 四阶段版 +

| 指标 | 判据 | 动作 1（站立→俯卧） | 动作 2（爬行） |
|---|---|---|---|
| 支撑相接触命中率（±4 mm 内） | ≥95% | — 无支撑相 | **100%** |
| 最大穿地 | ≤10 mm | **6.4 mm** | **7.7 mm** |
| 中间段（肘/膝/髋/肩）穿地 | ≤6 mm | **−0.5 mm**（净空） | **1.5 mm** |

| 前进方向/速度 | +X、误差<2% | — 只验姿态 | **0.500 m/s** |

normal 档：动作 1 为 6.5 / −2.3 mm、152.4 rad/s²（`r_hip_z`）、11.0°、0 帧自碰撞；

动作 1 的「—」是设计使然：过渡段没有支撑相（`contact_flags` 全 0）、脚是拖到位的、
也不要求匀速前进。验收脚本按 npz 里的 `action` 字段自动降级成 `[INFO]`。

上面九项**都查不出高频小幅的电机抖动**（详见 §3.4 末）：`check_prone_shake.py`
另有一条独立判据，两档下蹲段 `hip_x/hip_z` 二阶差分 rms 0.13/0.12°、
变号率 8.5%、主屈伸曲线 rmsD1 0.94/1.29°（没被抹钝），均通过。

另外一条**验收脚本没查、但 `check_prone_entry.py` 已核过**的判据：
u≥PLANT_U（0.44，手撑地）之后手掌不能重新离地（后伸期实测峰值 6.4 mm）。
早期版本曾出现 18 帧 / 峰值 98 mm 的"撑地后手又飘起来"，现由 `plant_clamp` 压到
**峰值 6.4 mm**（fast / normal 一致，v9 顺序判据已自动核对）。想复算：逐帧
`Kin.min_z(hand_geoms)` 即可。

关于「手漂 26 mm」：手是挂在腕外 4 cm 的球（局部 `(0.04,0,0)`，r=0.03），支撑相前臂转动
会让球心绕腕画弧，所以球心相对地面会滚 2~3 cm。这不是打滑，是手掌滚动。
试过按球心反解腕目标把它压到 0.4 mm，但会引入新的肘部翻越（关节速度 54 rad/s）并把
质心覆盖从 96% 拖到 80%，得不偿失。

## 7. 物理回放说明了什么

`prone_replay.py --mode phys` 用训练同款 kp/kd（`elf3_play.TrainParams`）做重力前馈 PD，
**四肢一律满增益**（`crab_replay.run_phys` 把手臂降到 0.3 倍是给站立设计的，爬行时手臂
承重，降增益必塌），力矩按 XML 的 `actuatorfrcrange` 夹一次。实测：

- 躯干高度 0.091~0.096 m（轨迹 0.096~0.104）—— **俯卧姿态能撑住**；
- 但循环段只前进 0.036 m / 目标 0.958 m（**推进率 4%**）；
- 四肢贴地保持率 15~66%（腿最差，脚浮起 7~14 cm）；
- 关节跟踪误差中位 45°（单帧最大），其中 waist 最吃力（中位 10.9°）。

结论：**开环 PD 能躺住但爬不动**，而且躯干姿态（自由基座）根本没被控制。这正是 RL 要补的
缺口：基座高度/姿态、支撑相接触力分配、摆动相落点，都必须闭环。所以 phys 模式只给诊断
数字，不设 PASS/FAIL；要验收动作序列本身用 `--mode kin`。

## 8. 已知限制 / 下一步

- **`--merge`（整段）已知不通过验收**，只作对照（2026-11-05 复测：中间段穿地 478 mm、
  滑移 1202 mm、a=3572 rad/s² @ f648、自碰撞 58 帧）。根因是 §2.6 说的接缝，
  且整段路径没有 `exit_q`，腿走不到爬行首帧的关节空间终点，会在最后几帧崩掉。
  过渡段兜底（`guard_floor` / `chain_clamp` / `plant_clamp` / `smooth_joint_window`）
  **只对 `p.cycles == 0` 的拆段动作 1 生效**，否则会把循环段摆动相的手也按到地上
  （实测 a=5483 rad/s²）。要用就用 `--split`，别修 `--merge`。
- **站距 y 加宽到 0.36 是为了质心判据**：手加宽（双臂分开）后，normal 档「对侧腿→支撑手」
  这条支撑三角上边缘在质心附近下旋，循环段质心占比掉到 62.7%（判据 95%），失败帧全在
  手臂摆动相。把 `leg_touch` 的 y 从 0.30 对称加宽到 0.36（fast 档不查质心，仍是 0.28）
  后回到 94.5%，再去掉侧摆 ramp（§3.3）到 **98.0%**。收窄任一列都会重新掉下去。
- **两个动作之间的姿态差几十度**（v7 实测 55°，`--no-join` 时）。默认 `--split` 会把动作 1 的末
  48 帧五次 Hermite 对齐到动作 2 首帧，两个 npz 可以直接连播（接缝基座差 0.02 mm、
  关节差 0.02°）；末端会有几毫米的偏移
  （`ground_clamp` + `plant_clamp` 已经兜过底）。
- **常规验收查不出「电机抖动」**：穿地 / 角加速度 / 自碰撞看的是峰值与下限，
  下蹲段 `hip_x`/`hip_z` 那种 ±1~5° 的高频反向噪声会全项 PASS，却是真机上最显眼的
  瑕疵。已由 `smooth_leg_joints()` 处理、并给 `check_prone_shake.py` 加了独立判据
  （§3.4 末）。改动作 1 或调 `leg_shake_sigma` 后两档都要重跑它。
- **动作 2 的腿仍有万向锁抖动**（`hip_z` 顶在 +95° 附近时 `hip_x` 与 `knee_y` 的解
  互换）。实测 f99 一帧里 `l_hip_x` 34.6°→31.6°→41.4°、`l_knee_y` 15.4°→9.8°→27.6°
  （单帧 9.8 / 17.8°），normal 档 300.8 rad/s² 的峰值就出自这里，不是「动作太快」。
  判据 400 余量偏薄但仍在界内；真要消除得把 `hip_z` 的目标设计成避开 ±90°
  （现在是 `hip_z` 一到 95° 就锁住，让 `hip_x`/`knee_y` 去凑同一个落点）。
- **v7 起就整段不下跪**：`kneel_weight()` 恒返回 0，v7 的下跪/贴地跪姿逻辑留在
  `_kneel_weight_v7()` 里没删。当年那版是「膝中心 58 mm、大腿胶囊 6.6 mm」的伪跪姿
  （大腿比膝粗，膝不可能先触地），视觉上像跪但没真接触。v9 的量证据 §3.4：
  膝胶囊最低全程 32~90 mm，始终悬空。
- **u≈0.80~0.95 腿会有一段平滑的离地鼓包**（fast 峰值 ≈80 mm @ f215~220，末帧
  回到 34 mm；normal 末帧 0.3 mm）。这是末段对齐到 gait 首帧的必然结果：gait 首帧
  本身就是「左腿抬起」的摆动相位，而收腿要把腿从矢状面伸直摊成蟹式。u<0.74
  （蹲下/撑地/后伸）的踝胶囊最低一直 −6~+5 mm，脚是贴地的。要结尾四肢全贴地，
  得改动作 2 的起始相位（或给循环加静止起手式），不能只在动作 1 里改。
- **`spread_hips()` / `lift_split_window()` 已停用**：10° 外展偏置与 14 mm 基座微抬
  是旧 IK 蛙式分支的补丁，关节空间路径不再需要（§3.4）。v9 要改的入口是
  `ENTRY_STAGES`（基座 z / 俯身 / `x_frac`）、`entry_keys`（手/脚世界系关键帧）、
  `EXIT_U=0.74` / `PLANT_U=0.44`、`Params.entry_ankle` / `entry_hip_z_limit`；
  改完先跑 `python scripts/check_prone_entry.py` 核对顺序，再用
  `check_prone_exit.py` 扫两档穿地/离地，别把这两个旧补丁加回来。
  `KNEEL_POSES` / `EXIT_TIMING_*` 现在只服务 `_kneel_weight_v7()`，改它们不影响轨迹。
- **验收脚本只查穿地、不查离地**：曾经有过「脚瞬时离地 433 mm、腿在空中划一圈」
  却仍全项 PASS 的版本。改后半段时务必同时看 `a1_legs_big.png` 或 GIF，不能只看报告。
- 只验证了平地，没有障碍物。
- 手臂跨在头两侧、手落在头前 0.1 m，视觉上比较"挤"；想更宽松可以调
  `arm_touch=(0.30, 0.36)`（手往体侧收），但会压缩前后扫掠的可达余量。
- 没有导出给 mjlab 的参考表（`train/assets/ref_tables/` 里是 `crab_ref_v1.npz` 那套
  `q[root, tread, frames, 29]` 结构，本轨迹是单档平地，需要另外定义键）。下一步训练时再补。
- 过渡段脚是"拖"到位的（设计上允许滑），所以验收脚本的滑移只统计循环段。

### 9.1 为什么自己拼，而不是用 `--merge`

`run_crawl.sh --merge` 产出的 `prone_crawl_traj.npz` 是 join 版（两段一起求解），
接缝处二阶差分 514 rad/s²，是当初拆段的直接原因；而且它的 `meta` 里还是旧参数。
**split 版才是对的起点**：`build_split()` 用 `blend_tail_to(48)` 把动作 1 末 48 帧
五次 Hermite 对齐到动作 2 首帧，实测 `qpos` 差 **1.29e-4 rad**（fast 1.36e-4）。

拼接时**丢掉动作 2 的首帧** —— 它与动作 1 末帧几乎完全重复，留着会多一次 20 ms
定格。结果 normal 档 250 + 399 = **649 帧 / 12.98 s**，X 向推进 1.098 m；
fast 档 250 + 169 = 419 帧 / 8.38 s。接缝处角加速度 223.7 rad/s²，
低于 gait 段自身的峰值，不是新的最差点。`meta.sequence` 存分段边界、接缝残差、
每循环推进量；`--cycles N` 可以把爬行段重复 N 遍并按 `travel` 累加基座 x
（不累加会让第二个循环把机器人瞬移回原点）。

### 9.2 38 → 36 维与两种"落地"判据

网页模型 `web/assets/elf3.xml` 是 nq=36（少 `head_z/head_y`），
`bake_crawl.py` 复用 `bake_squat.build_qpos_remap()` **按关节名**取列。
源 qpos 的四元数只保留 4 位小数（范数偏 7.45e-5），烘焙时统一归一化 ——
网页端 `mj_kinematics` 不会替你归一化，非单位四元数会让旋转矩阵轻微缩放。

**不能照抄蹲起 / 正步的「脚底全程贴地」判据**：趴姿时脚在身后抬起，
接触点是手 + 躯干。这里只查开头 60 帧（站姿段）视觉最低点 -0.73~-0.57 cm，
以及全程最低点不低于 -12 cm（防整体陷地）。

**已知视觉遗留（源轨迹固有，不是重映射出错）**：撑地瞬间 f107 左右手 mesh
最低 **-8.95 cm**、趴姿段约 -5 cm。`elf3_prone.xml` 与 web 端用的是同一份
`l_hand.STL` / `r_hand.STL`（md5 一致）、同样的编译期 `geom_pos/quat`，
两端逐帧算出来的数字完全一样；数值验收只看碰撞代理（腕部 r=0.05 球），
所以一直没查出来。别用 `--z-offset` 硬抬 9 cm（站立时脚会整体离地），
也别改手腕姿态（会与真机轨迹不一致）；真要消除得改动作 1 的手腕朝向设计。
`motion_crawl.json` 的 `stats.visualMinZCm` / `handMinZCm` 如实记录了这个值。

### 9.3 网页端行为

`kind="crawl"`、`loop=false` + `freezeAtEnd=true`（播完冻结在趴姿，不跳回站立），
`camera="crawl"` 专用低机位 `[1.65, 1.02, -1.10] → [0, 0.42, -0.15]`：
站姿 1.03 m 到趴姿 0.10 m 都得在画面里，目标点必须压到 0.42 m。
这段回放还把视角跟随的 lerp 从默认 0.07 单独提到 **0.25** —— 它沿 three -Z
推进 1.1 m 且包围盒中心下降约 0.57 m，低帧率（无头浏览器实测 8~10 fps）下
0.07/帧收敛太慢，末帧机器人会被挤到画面右下裁掉。

菜单项「参考动作 · 贴地爬行（蹲下→撑地→后伸→爬行）」，
也可直接开 `?motion=crawl&scene=single`（矩阵 10×20 的机位太远，看不清贴地细节）。
`web/tools/verify.mjs` 里加了 5 条专项断言：下拉项存在、649 帧 / 播完冻结、
z 1.034→0.099、分段 250+399 / 接缝 f250、自动切低机位。

快档可用 `python web/tools/bake_crawl.py --preset fast --name crawl_fast`
另出一份，但它的单帧关节跳变 0.4477 rad（动作 2 的万向锁抖动被 0.85 s 周期放大），
网页回放会明显顿挫，所以**默认只下发 normal 档**。

# 螃蟹步爬楼梯 —— 强化学习训练设计说明

> 本文给出「侧向（螃蟹步）爬楼梯」从脚本步态升级为带闭环反馈策略的完整训练设计：
> 任务建模、策略与观测/动作、并发规模、奖励函数、PPO 超参、课程、域随机化、监控与验收。
>
> **定位**：路线 A（残差 RL）。脚本步态作为基础动作（`crab_climb.py` 生成 `q_ref`），
> 策略只输出修正量 `Δq`，不从头学步态。这样初值就能爬，训练量小、收敛快。
>
> **与代码的关系**：本文数字中，标「实测」的取自现有仿真；标「建议初值」的是训练超参，
> 需在服务器上按实际收敛情况微调。训练环境用 **mjlab（MuJoCo Warp）**，资产直接复用
> `elf3.xml` + `scene_crab.xml`，与仿真/网页同源。

## 1. 任务建模

### 1.1 坐标系与运动方向（本项目最容易被抄错的地方）

| 项 | 值 | 说明 |
|---|---|---|
| 机器人朝向 | 面朝 **+X** | 不是面朝台阶 |
| 台阶上升方向 | 沿 **+Y** | 侧向上楼 |
| 台阶剖面所在平面 | **YZ** 平面 | 所以虚拟相机要站 ±X 侧（`az=160`） |
| 前进指令 | `v_cmd = (0, v_y, 0)` | **progress / 速度奖励必须在世界系 `+Y` 上算** |

> 坑：多数 humanoid 楼梯模板默认「面朝台阶、沿 +X 上楼」。直接套用会让策略学到
> 「往前撞墙」。所有推进类奖励项都要显式用世界系 `+Y`，不要用 body 前向轴。

### 1.2 状态/动作空间

**可控关节共 29 个**（头部 2 个 `head_z/head_y` 不控；`world_joint` 为自由关节，不控）：

| 部位 | 关节 | 数量 |
|---|---|---|
| 腰 | `waist_y / waist_x / waist_z` | 3 |
| 左腿 | `l_hip_y / l_hip_x / l_hip_z / l_knee_y / l_ankle_y / l_ankle_x` | 6 |
| 右腿 | 同左腿（`r_*`） | 6 |
| 左臂 | `l_shoulder_y/x/z / l_elbow_y / l_wrist_x/y/z` | 7 |
| 右臂 | 同左臂（`r_*`） | 7 |
| **合计** | | **29** |

- `nq = 38`（自由关节 7 + 铰链 31）；网页模型去掉头部 2 关节后 `nq = 36`，前 36 维顺序一致。
- **动作维数 = 29**，即 29 个目标关节角（残差形式）。
- 头部关节在训练中固定为默认位，不参与动作。

### 1.3 时间尺度（实测）

| 层 | 频率 | 步长 | 说明 |
|---|---|---|---|
| 物理 | **500 Hz** | `dt_phys = 0.002` | MuJoCo 积分 |
| 控制 | **50 Hz** | `dt_ctrl = 0.02` | decimation = 10 |
| 步态周期 | — | `step_time = 0.9 s`，`hold = 0.5 s` | 单腿摆动 0.9 s，过渡保持 0.5 s |
| 摆腿离地余量 | — | `clearance = 0.055 m` | 过踏面边界的抬脚高度 |

- 轨迹规划 `crab_climb.py` 以 `dt=0.02` 输出，与策略控制频率一致，可直接作为 `q_ref`。
- 一个控制步 = 10 个物理步；策略每 10 个物理步推理一次。

### 1.4 地形参数域（来自 `crab_config.json`）

| 参数 | 默认 | 训练随机范围（建议） | 含义 |
|---|---|---|---|
| `n_up` | 6 | 4–8 | 上升级数 |
| `n_down` | 3 | 2–4 | 平台后下降级数 |
| `rise` | 0.12–0.25 | **0.10–0.22** | 单级高度 |
| `tread` | 0.20–0.40 | **0.24–0.40** | 踏面深度 |
| `width` | 1.2 | 1.0–1.4 | 台阶宽度 |
| `landing_depth` | 0.30 | 0.25–0.40 | 顶部平台进深 |
| `seed` | 42 | **每个 env 不同** | 地形随机种子 |

> 坑：**绝不能用单一楼梯训练**（固定 seed）。这是这类任务最常见的过拟合来源：
> 策略会记住某一级固定高度/深度的落脚点，换一套楼梯立刻崩。并发环境里每个 env
> reset 时都要按参数域重新采样，且 **跨 env 的 seed 必须互不相同**。

## 2. 策略设计

### 2.1 为什么用残差 RL 而不是从零 PPO

现有闭式 IK 控制器的问题已量化：**43% 的帧质心落在支撑多边形外，最长连续 0.24 s**
（`L4` 降级档同样 43%）。根因是脚掌 box 几何叠加开环轨迹，无反馈能力，调参无法解决。
残差 RL 的价值在于：

- `q_ref` 已经保证「大致会爬」，策略只需学「怎么在扰动/几何误差下不摔」；
- 探索空间小、样本效率高，平地起步即可获得正回报；
- 训练失败时仍能退回纯脚本步态，风险可控。

### 2.2 网络结构

| 项 | 设置 |
|---|---|
| 类型 | MLP + 对角高斯策略（Actor-Critic 共享或分离躯干） |
| 隐层 | **256 → 128 → 64**，激活 **ELU**（也可 Tanh） |
| 输出 | 29 维均值 `μ`；`log_std` 为可学习向量（初值 −1.0，约 `σ≈0.37`） |
| 价值网络 | 同构 MLP，输出标量 `V(s)` |
| 参数量 | 约 12 万（轻量，适合 50 Hz 高频推理） |

> 若后期加深度感知（路线 C），在躯干前接一个 CNN（输入 42×64 深度图），
> 但那是另一套工程，**本文不涉及**。

### 2.3 观测向量（108 维，逐项）

| # | 组成 | 维数 | 归一化/说明 |
|---|---|---|---|
| 1 | base 角速度（body 系） | 3 | ×0.25 |
| 2 | 投影重力（body 系重力方向） | 3 | 已单位化 |
| 3 | base 线速度（body 系） | 3 | ×2.0 |
| 4 | 关节角（相对默认位） | 29 | ×1.0 |
| 5 | 关节角速度 | 29 | ×0.05 |
| 6 | 上一步动作 | 29 | 原值 |
| 7 | 步态相位钟 `sin/cos` | 2 | 由 `t / step_time` 生成 |
| 8 | 速度指令 `(v_x, v_y)` | 2 | 目标 `v_y ∈ [0.15, 0.25]` |
| 9 | 四足端相对本地地形高度 | 4 | 米 |
| 10 | 四足接触标志 | 4 | 0/1 |
| | **合计** | **108** | |

> 部署到真机若无 base 线速度估计，可去掉第 3 项降为 **105 维**（训练时用
> 观测掩码随机置零，让策略适应缺失）。

### 2.4 动作与残差限幅

```
q_target = q_ref(t) + clip(Δq, -Δmax, +Δmax)
```

| 部位 | `Δmax` | 理由 |
|---|---|---|
| 髋/膝/踝（12） | **±0.30 rad** | 给足修正余量，又不至于把步态改烂 |
| 腰（3） | ±0.15 rad | 只做小幅姿态补偿 |
| 臂（14） | ±0.15 rad | 主要起平衡，幅度小 |

- `q_ref(t)` 由 `crab_climb.py` 的四相位轨迹在训练时**同步生成**（不是回放 npz），
  每个 env 有自己的相位偏移，避免所有环境同相位导致梯度同向震荡。
- 输出经 PD 控制器转力矩：`τ = kp·(q_target − q) − kd·q̇`，`kp/kd` 沿用仿真里
  `elf3_play.py` 的 actuator 增益（训练/回放必须一致）。

### 2.5 动作平滑

- 动作限幅后做一阶低通：`a_t = 0.8·a_{t-1} + 0.2·a_raw`（可选，减小高频抖动）。
- 奖励里对 `‖a_t − a_{t−1}‖²` 与 `‖q̈‖²` 直接惩罚，双保险。

## 3. 并发数与吞吐

### 3.1 `num_envs` 选型（mjlab / MuJoCo Warp，单卡）

| GPU | 显存 | 建议 `num_envs` | 备注 |
|---|---|---|---|
| RTX 4090 | 24 G | **4096** | 性价比首选 |
| RTX 3090 | 24 G | 3072 | 算力略低，先按 3072 试 |
| L40S | 48 G | 8192 | 显存充裕 |
| A100 80G | 80 G | 12288–16384 | 大 batch 更稳 |

- **起步用 2048** 确认 reward 不崩、显存有余，再翻倍到 4096。
- 每个 env 独立地形 + 独立相位偏移 + 独立域随机化参数。

### 3.2 rollout / batch 计算

| 项 | 值 | 计算 |
|---|---|---|
| `num_envs` | 4096 | — |
| `num_steps_per_env`（rollout 长度） | **24** | 24 × 0.02 s = 0.48 s 轨迹 |
| 每轮采样数 | **98,304** | 4096 × 24 |
| `num_mini_batches` | 4 | 每个 minibatch 24,576 |
| `num_learning_epochs` | 5 | 每轮数据复用 5 次 |
| 每轮梯度步数 | 20 | 4 × 5 |

> rollout 长度 24 约等于半个步态周期（0.9 s），能覆盖一次摆腿；若策略学不会
> 长程平衡，可增加到 32（0.64 s）。

### 3.3 吞吐估算（经验值，非承诺）

- 4096 env × 50 Hz 控制 = 每「仿真秒」20.5 万个控制步；物理步 ×10 = 205 万。
- mjlab 在 4090 上大致 **1–5 s / 迭代**（含前向 + PPO 更新），2000 迭代约 **1–3 小时**；
- 完整课程（含地形逐级收紧与成功率筛选）**1–2 天**出可用策略。
- 瓶颈通常在 **CPU 侧的地形生成与 reset**，不在 GPU；地形生成要缓存/预生成，
  不要每步都重建。

### 3.4 CPU 与显存

| 项 | 建议 |
|---|---|
| CPU 核数 | ≥ 16（地形生成 + 离屏渲染在主进程） |
| 单 env 显存 | 约 3–5 MB（4096 env ≈ 20 G 内） |
| 日志/checkpoint | 每 50 iter 落盘一次，竞价实例必备 |

## 4. 奖励函数（成败关键）

### 4.1 设计原则

1. **推进项必须是主项**，权重压过所有正则项，否则策略学会「站着不动最安全」。
2. 姿态/高度用 **exp 核**而非二次惩罚，梯度更平滑，避免「差一点就爆炸」。
3. 步态项只做**引导**，不强制精确复现 `q_ref`（否则退化成行为克隆，失去反馈意义）。
4. 惩罚项要**可归因**：碰撞、打滑、横滚各自独立，方便看曲线定位问题。
5. 每步总奖励量级控制在 **0.5–2.0**，过大导致 value loss 难收敛。

### 4.2 逐项定义（建议初值）

记 `Δt = 0.02 s`，`y` 为世界系前进方向（+Y），`h` 为 base 高度。

| # | 名称 | 公式 | 权重 | 作用 / 失效表现 |
|---|---|---|---|---|
| 1 | 前进进度 | `r_prog = clip((y_t − y_{t−1})/Δt, 0, v_max)` | **+1.0** | 主项；缺失则原地不动 |
| 2 | 速度跟踪 | `r_v = exp(−‖v_xy − v_cmd‖²/0.25)` | **+0.5** | 平滑推进；过大会牺牲稳定性 |
| 3 | 竖直姿态 | `r_up = (ĝ_z)²`（`ĝ` 为 body 系重力单位向量 z 分量） | +0.3 | 防倾倒；过大会僵硬 |
| 4 | 髋高跟踪 | `r_h = exp(−(h − h_ref(y))²/0.01)` | +0.4 | `h_ref(y)` 由地形高度查表；防蹲/站太高 |
| 5 | 摆动腿离地 | `r_clr = exp(−(h_foot − h_terrain − clearance)²/0.0025)`，仅摆动相 | +0.3 | 防拖地/绊台阶 |
| 6 | 落脚点 | `r_foot = exp(−(p_foot,y − y_center)²/0.01)`，仅触地瞬间 | +0.3 | 落到踏面中心；防踩边 |
| 7 | 支撑脚不滑 | `r_slip = ‖v_foot‖²`，仅支撑相 | **−0.3** | 防「滑着上楼」 |
| 8 | 动作平滑 | `r_ar = ‖a_t − a_{t−1}‖²` | **−0.05** | 防抽筋式高频抖动 |
| 9 | 关节加速度 | `r_ja = ‖q̈‖²` | −0.001 | 抑制冲击 |
| 10 | 力矩能耗 | `r_τ = ‖τ‖²` | −0.0005 | 省电、更自然人形 |
| 11 | 非足部位碰撞 | `r_col = 1[非足 geom 接触台阶]` | **−2.0** | 膝/髋撞台阶，必须重罚 |
| 12 | 横滚/俯仰 | `r_rp = roll² + pitch²` | −0.5 | 防侧翻（螃蟹步尤其看横滚） |
| 13 | 横向漂移 | `r_lat = (x − x_0)²` | −0.2 | 保持沿台阶走，不歪 |
| 14 | 存活 | `r_alive = 1`（每步） | +0.1 | 与推进项配对，防早死 |
| 15 | 终止惩罚 | `r_term = 1[terminated]` | **−5.0**（一次性） | 明确「摔了很糟」 |

**总奖励**：`r_t = Σ w_i · r_i`，episode return 为各步之和。

### 4.3 终止条件

| 条件 | 阈值 | 说明 |
|---|---|---|
| base 高度过低 | `h < h_ref − 0.15 m` | 摔倒 |
| 横滚/俯仰过大 | `abs(roll) > 0.6 rad` 或 `abs(pitch) > 0.6 rad` | 侧翻/前扑 |
| 非足部位持续接触 | 连续 5 步 | 撞台阶卡住 |
| 无进展超时 | 2 s 内 `Δy < 0.02 m` | 原地磨蹭 |
| 越界 | `abs(x) > 1.5 m` 或 `y < −0.5 m` | 跑飞 |

### 4.4 奖励量级校准

- 每步理想总奖励 ≈ **0.8–1.5**；若 `r_prog` 单步就 > 3，说明 `v_max` 设太大或速度过快。
- 训练前先跑 **随机策略 1000 步**，看 `r_prog` 均值是否接近 0、碰撞惩罚是否偶发；
  若随机策略就拿到很高回报，说明奖励有漏洞（例如「站着也算存活」）。
- 建议先只开 `#1/#2/#3/#4/#11/#15`，确认能爬；再逐项加 `#5–#10/#12–#14`。

### 4.5 常见失败模式 → 改法

| 现象 | 可能原因 | 改法 |
|---|---|---|
| 原地抖动不前进 | 平滑惩罚过重 / 推进项太弱 | 降 `#8` 到 −0.02，提 `#1` 到 1.5 |
| 高频抽筋 | 脚掌 box 穿透导致动力学跳变 | 调软 `solimp/solref`，或改 4 点接触 |
| 蹭着台阶贴上去 | 落脚点项缺失/过弱 | 提 `#6`，并加 `#7` 打滑惩罚 |
| 只在一级台阶上成功 | 单一地形过拟合 | 强制每 env 不同 seed + 扩大 `rise/tread` 范围 |
| 一上台阶就侧翻 | 横滚惩罚不足 | 提 `#12`，并在域随机化里加初始横滚扰动 |
| 退化成「爬行」 | 姿态项过强 | 降 `#3/#4`，保留推进主项 |

## 6. 课程学习（不要一上来就完整楼梯）

| 阶段 | 地形 | `rise` | `tread` | 升级条件 |
|---|---|---|---|---|
| 0 | 平地站立/原地 | 0 | — | 存活 > 90% |
| 1 | 单级台阶 | 0.10 | 0.40 | 成功率 > 80% |
| 2 | 两级台阶 | 0.12 | 0.35 | 成功率 > 80% |
| 3 | 完整楼梯（缓） | 0.12–0.18 | 0.30–0.40 | 成功率 > 80% |
| 4 | 完整楼梯（标准） | 0.12–0.22 | 0.24–0.40 | 成功率 > 80% |
| 5 | 完整楼梯（难） | 0.15–0.25 | 0.20–0.32 | 保持 > 70% 即停 |

- 每阶段的成功率按**滑动窗口 100 episode**统计，避免偶然波动。
- 降级机制：某阶段成功率跌到 50% 以下，回退上一阶段跑 200 iter 再升。

## 7. 域随机化（sim2real 与鲁棒性）

| 项 | 范围 | 说明 |
|---|---|---|
| 摩擦系数 | 0.4–1.2 | 地面/台阶 |
| 躯干质量 | ±10% | — |
| 电机力矩 | ±15% | actuator 增益缩放 |
| 关节零位偏移 | ±0.02 rad | 编码器误差 |
| 观测噪声 | 高斯，σ = 0.01–0.02 | 按量纲缩放 |
| actuator 延迟 | 1–3 个控制步 | 关键，显著提升鲁棒性 |
| 外部推力 | 每 100 步随机 50–150 N，持续 0.1 s | 抗扰 |
| 初始位姿扰动 | 位置 ±2 cm，姿态 ±0.05 rad | — |

## 8. 训练配置模板（mjlab 风格，需按实际 API 调整）

> 下面是**结构模板**，字段名以你安装的 mjlab 版本为准；核心是「观测/动作/奖励/终止/
> 课程/域随机化」六块配置齐全。

```yaml
task: Elf3CrabStairs
robot: elf3            # 复用 data/mujoco_simulation/elf3.xml
scene: scene_crab      # 复用 web/assets/scene_crab.xml 的 include

sim:
  timestep: 0.002
  decimation: 10       # -> 控制 50 Hz
  substeps: 1

env:
  num_envs: 4096
  episode_length_s: 20
  action_dim: 29
  obs_dim: 108

terrain:
  kind: stairs_crab
  n_up: [4, 8]
  n_down: [2, 4]
  rise: [0.10, 0.22]
  tread: [0.24, 0.40]
  width: [1.0, 1.4]
  landing_depth: [0.25, 0.40]
  per_env_seed: true

policy:
  type: residual
  residual_clip: {legs: 0.30, waist: 0.15, arms: 0.15}
  hidden: [256, 128, 64]
  activation: elu

reward:
  progress:        {weight: 1.0}
  vel_track:       {weight: 0.5, sigma: 0.25}
  upright:         {weight: 0.3}
  height_track:    {weight: 0.4, sigma: 0.10}
  swing_clearance: {weight: 0.3, clearance: 0.055}
```

## 9. 训练流程

```bash
# 1) 建环境（云端）
bash scripts/bootstrap_gpu.sh
source .venv/bin/activate

# 2) 冒烟：随机策略 1000 步，确认奖励项无异常、显存够
#    （具体入口以 mjlab 为准，下为示意）
python -m mjlab.train --task Elf3CrabStairs --num_envs 512 --iterations 5 --dry-run

# 3) 小规模验证：2048 env，跑 200 iter，看 reward 是否上升
python -m mjlab.train --task Elf3CrabStairs --num_envs 2048 --iterations 200

# 4) 正式训练：4096 env + 完整课程
python -m mjlab.train --task Elf3CrabStairs --num_envs 4096 --iterations 3000 \
  --logdir logs/crab_rl

# 5) 导出 ONNX（供 crab_replay --mode phys / 网页回放）
python -m mjlab.export --checkpoint logs/crab_rl/model_3000.pt --format onnx
```

## 10. 监控与验收指标

### 10.1 训练期监控（每 10 iter 打点）

| 指标 | 期望趋势 |
|---|---|
| `episode_return` | 单调上升后平台 |
| `mean_progress_y` | 上升，最终 > 楼梯总高 |
| `success_rate` | 随课程上升，每阶段 > 0.8 |
| `fall_rate` | 下降 |
| `com_support_ratio` | **从 43% → > 85%**（核心） |
| `foot_slip` | 下降 |
| `torque_rms` | 平稳，不异常尖峰 |
| `kl_divergence` | < 0.02，超标自动降 lr |

### 10.2 验收（训练后）

| 检查 | 通过标准 |
|---|---|
| **质心在支撑面内帧占比** | **> 85%**（baseline 43%） |
| 最长连续越界时长 | < 0.10 s（baseline 0.24 s） |
| 完整楼梯成功率 | > 80%（100 次随机地形） |
| 落脚点误差 | 踏面中心 ±3 cm |
| 爬完 6 级耗时 | 与脚本步态同量级，不显著变慢 |
| 泛化 | 换 seed/尺寸后成功率下降 < 10% |

### 10.3 与回放/网页的衔接

```
训练 → 导出 ONNX → framework/inference 的 ModelSpec → crab_replay.py --mode phys
      → bake_crab.py → web/assets/motion_crab.bin/json → 网页回放
```

验收就用现有链路：`crab_replay.py --mode phys` 看是否摔、`bake_crab.py` 烘到网页看回放。
